## Preflight

After deployment, run:

```bash
npm run agent:registry:check -- --base-url=https://redqueen.space
```

This verifies metadata, OASF, x402 and a real MCP initialize handshake. It does not create or submit a transaction.

## Mainnet registration

The Agent Asset was registered by the project wallet with the intended SDK operation:

```ts
registerAgent("https://redqueen.space/.well-known/agent-registration.json", {
  atomEnabled: false,
});
```

ATOM reputation remains disabled for the initial registration. It can be enabled later, but enabling it is one-way for the Agent Asset.

The registered identity is verified through the public Agent Asset, metadata URI and registration transaction. `RED_QUEEN_AGENT_ASSET` and `RED_QUEEN_AGENT_REGISTRATION_TX` must remain configured in production.

## Operational wallet binding

Operational-wallet binding is a separate owner-controlled action exposed in the Onchain identity card. It never asks for a seed phrase or project private key. The connected project wallet must:

1. Sign a canonical `8004_WALLET_SET` proof message. This is off-chain and moves nothing.
2. Review a separate transaction containing only the Ed25519 proof instruction and the 8004 `setAgentWallet` instruction.
3. Approve the Solana mainnet network fee.
4. Wait for the server to confirm the transaction and re-read the operational wallet from the Agent Asset.

The current public flow only allows the configured Agent Asset owner to bind that same project wallet. It rejects a different wallet, unexpected program, asset, signer, fee payer, instruction count, deadline or embedded proof message.

No private key belongs in the repository or browser-visible environment variables.
